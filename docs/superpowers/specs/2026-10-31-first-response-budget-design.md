# Codex first-response waiting budget

The user approved a real first-response deadline with safe credential failover, with a 30-second total budget for ordinary requests. Existing bootstrap buffering only releases headers; it does not cancel a silent upstream. A request must not repeatedly receive a fresh full waiting budget when switching credentials.

Implement an opt-in Codex HTTP streaming policy: total waiting budget 30s, per-attempt ceiling 15s, and at most two attempts across credential retry rounds. The total starts at the manager request entry and remains shared across attempts. A cancelled attempt must release its Home execution before selecting the next account. A local deadline must not mark an account as invalid or impose an upstream-failure cooldown. Cancellation by the caller takes precedence.

Determine eligibility from the finalized upstream payload. Absent/none/minimal/low/medium reasoning and payloads no larger than 256 KiB are ordinary. High/xhigh/max/ultra, unknown reasoning, and larger payloads retain existing behavior. The byte threshold is a conservative size guard, not a token count. These defaults are implementation choices; total and attempt duration plus byte threshold are configurable. Default total 0 disables the policy for existing deployments; document an explicit 30s/15s deployment configuration.

Keep metadata/heartbeats uncommitted while the policy is pending. A substantive event, tool-start event, or unrecognized event stops the deadline atomically before delivery. Existing long streams continue without a new lifetime timeout. If buffering would exceed its memory/frame bound, terminate safely rather than silently resetting the budget or retaining unbounded data. A remote tool can begin before its notification arrives, so cancellation cannot promise rollback of upstream work.

Scope: the Codex HTTP streaming executor used by the measured production traffic. WebSockets, non-streaming aggregation, compact/image endpoints and other providers retain existing behavior. Home v1.1.7 distributes raw configuration YAML; no Home implementation change is required. This explicitly authorized opt-in pre-response policy is a narrow exception to AGENTS.md's general prohibition on post-connect network timeouts.

Home v1.1.7 also turns indexed failed 502/504 usage records into credential-health failures, ignoring the structured failure code. For typed local first-response policy errors only, publish the failed usage with an empty scheduler `AuthIndex`, preserving the actual status (504 deadline, 502 buffer bound), account source/email, credential ID, request IDs, timing and token details. Keep the original credential index in structured application diagnostics. Real upstream 502/504s and caller cancellation retain their existing attribution; publishing must not mutate the reporter's stored identity.

Alternatives considered: reducing credential attempts from two to one only removes the second wait; a whole-request timeout would also kill healthy long answers. The chosen policy bounds waiting before progress while retaining one safe failover opportunity. It may return a timeout for requests that would eventually succeed; it does not make an overloaded upstream generate faster.

Initial Home acquisition precedes final-payload eligibility, so this policy counts that time but cannot interrupt that initial acquisition; existing Home acquisition timeouts remain in force. Once active, remaining-budget cancellation also covers retry acquisition, preparation, cooldown and release acknowledgements. Mixed-provider routes are excluded to preserve their existing semantics.
